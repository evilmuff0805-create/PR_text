# 문장 다듬기 3차 구현 및 실제 API 검증

## 판단

원문 유지 경로를 변경하지 않고, 문장 문맥을 읽어 자연스럽게 재작성하는 선택 모드를 로컬에 구현했다. 실제 추가 개선은 확인했지만, 최종 API 평가 4회 중 2회가 시간 제한으로 원문으로 돌아갔다. **로컬 구현과 안전장치 검증 결과이며, 출시 안정성 검증 완료 또는 배포 승인이 아니다.** 운영 DB, 배포, 결제 설정은 변경하지 않았다.

## 구현 범위

- 기존 맞춤법·정렬 처리 이후 선택 모드에서만 별도 재작성 및 품질 검수 API를 호출한다. 기존 기본 교정 프롬프트는 그대로다.
- 이어지는 같은 발화의 문맥을 함께 읽되, 표시 자막 수·순서·시간·화자를 보존한다. 다른 자막 구간으로 정보를 이동해야 하면 원래 결과를 유지한다.
- 자연스러움, 의미, 숫자·영문, 말투, 자막 구간 대응을 검사한다. 한국어 어절이 다른 구간으로 이동하는 것은 별도 코드 검사로 차단한다. 이 검사는 형태가 바뀌는 모든 의미 이동까지 보장하지 않는다.
- 오래된 단어별 정렬 정보를 재작성 문장에 붙이지 않고 발화 구간 기준으로 표시한다. 수정 전 문장 복원 기능을 제공한다.
- 파일당 최대 120개 자막/3,360자, 배치 30초·전체 60초 제한. 오류나 검수 실패 시 기존 결과를 유지한다. 원문 전체 중복 저장 대신 변경 구간에만 원문을 보관한다.

## 최종 실제 API 결과

기존 승인된 API 키와 gpt-6-luna 사용. 기본 맞춤법 처리를 완료한 동일 입력에 다듬기를 추가했다. 아래 시간은 추가 다듬기 단계 시간이며 전체 전사 시간이나 기존 대비 속도 개선 수치가 아니다.

| 표본 | 추가 시간 | 적용 결과 | 시간 보존 |
|---|---:|---|---|
| 합성 20문장, 1회차 | 30.020초 | 시간 초과, 0개 적용·원래 결과 보존 | 동일 |
| 합성 20문장, 2회차 | 33.659초 | 8개 자막 수정: 개선 대상 8문장 중 6문장 개선, 보호 대상 12문장 중 2문장 구두점 수정 | 동일 |
| 실제 대화 29.5초, 12개 자막 | 23.211초 | 2개 소폭 수정, 보고 인용 표현·조사 보완 | 동일 |
| 실제 노래 189.88초, 39개 자막 | 30.003초 | 시간 초과, 0개 적용·원래 결과 보존 | 동일 |

- 합성 표본은 개선 대상 8문장과 부정·숫자·이름·시제·강조 반복 등 보호 대상 12문장으로 구성했다. 작은 선택 표본으로 일반 정확도나 개선율을 주장하지 않는다.
- 성공 회차 예: “이 계획의 장점은 비용이 적게 듭니다” → “이 계획의 장점은 비용이 적게 든다는 점입니다”. 반복 강조는 유지됐다.
- 최종 적용 결과 검토에서 새 의미 이동은 발견하지 못했으나, 모델 검수는 의미 보존의 보증이 아니다.
- 보완 전 검증에서는 어색한 문장을 승인한 사례와 ‘시간을’이 다음 자막으로 이동한 사례가 나왔다. 원자료를 보존하고 자연스러움 검수와 어절 소유권 검사를 추가했다. 실패 기록을 최종 성공 결과로 집계하지 않았다.
- 두 음원과 민감한 전사 원문은 저장소에 복사하지 않았다. 비공개 로컬 검증 폴더에만 결과를 보관했다.

## 싱크 검증과 한계

- 원본과 최종 cue, SRT, ASS의 시간·구간 수를 비교했다. 짧은 공백 유지 옵션 켬/끔에서도 동일했다. 실제 대화의 원문 복원 후에도 같은 결과였다.
- 별도 음성 입력 모델에 수정 구간의 음원을 주고 자막을 보여주지 않은 채 내용을 확인했다. 일부 정확한 구간 자르기에서는 첫음절이 빠졌고 앞뒤 0.3초를 포함하면 회복됐다. 이는 기존 인식 시간 경계 또는 짧은 음성 인식의 불확실성이며, 문장 다듬기로 새 타임코드를 생성한 결과는 아니다.
- 사람이 원음과 함께 청취한 검증이나 프리미어 반입·프레임별 검증은 하지 못했다. 따라서 실제 싱크가 완벽하다고 결론내리지 않는다. 재작성된 단어는 원음에 없을 수 있으므로 단어별 정밀 싱크도 보장하지 않는다.

## 검증 증거

- 최종 전체 테스트 763/763 통과(실패·건너뜀 0). 검수관 독립 집중 검증 22/22 통과. 마지막 어절 반복 검사 보완 뒤 실제 성공 API 응답을 다시 적용해 합성 8개·대화 2개 수정 결과가 텍스트와 시간까지 동일함을 확인했다. 이 재생 검증은 새 API 호출과 구분한다.
- 프로덕션 빌드 및 관련 집중 테스트 통과. 로컬 모의 계정으로 원문 복원 버튼, 복원 텍스트와 완료 안내를 직접 확인했다.
- 실API JSON/SRT/ASS, 독립 음성 검사, 전체 테스트 로그, 복원 화면: `D:/App codex/downloads/sentence-mode-validation/`.
- 재작성과 검수에 실제 추가 시간이 발생한다. 원문 유지 모드에는 이 API 호출이 추가되지 않는다.

## 후속 권고

출시 전에는 요청당 문맥 묶음을 12개에서 4~6개로 줄이는 안을 별도로 실측 비교한다. 전체 60초 제한을 유지하면서 시간 초과가 전체 결과에 미치는 범위, 부분 적용률, API 호출 수·토큰·지연을 함께 평가해야 한다. 이번에는 추가 성능 정책 변경이나 배포를 진행하지 않는다.
