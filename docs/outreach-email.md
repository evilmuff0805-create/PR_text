# 코드밋 홍보 메일 관리자

이 기능은 `/admin/outreach`에서 채널 후보와 수신 동의가 확인된 업무용 연락처를 관리하고 서비스 소개 메일을 발송한다. 담당자, 발신자와 회신 주소는 각각 `코드밋`, `codemeet@naver.com`, `codemeet@naver.com`으로 고정한다. 기존 회원의 이메일이나 회원가입 정보를 홍보 연락처로 가져오지 않는다.

## 준비할 설정

| 서버 환경변수 | 용도 |
| --- | --- |
| `OUTREACH_ADMIN_USER_IDS` | 접속을 허용할 Supabase 사용자 UUID. 여러 명이면 쉼표로 구분한다. 이메일 일치나 사용자가 편집할 수 있는 메타데이터로 권한을 부여하지 않는다. |
| `YOUTUBE_API_KEY` | YouTube Data API v3를 활성화한 서버용 키. Google API 제한과 서비스의 고정 출구 IP가 있다면 IP 제한도 설정한다. 브라우저에 전달하지 않는다. |
| `OUTREACH_SMTP_PASSWORD` | `codemeet@naver.com` 계정의 네이버 애플리케이션 비밀번호. 서버의 비밀 환경변수로만 등록한다. |
| `OUTREACH_SMTP_PORT` | 기본 `587`과 필수 STARTTLS. `465`를 선택하면 암시적 TLS를 사용한다. 인증서 검증을 끄지 않는다. |
| `OUTREACH_SENDING_ENABLED` | 기본 `false`. 발송 준비를 검증한 다음 명시적으로 `true`로 전환한다. 본인 테스트 발송에도 필요하다. |
| `OUTREACH_SEND_INTERVAL_SECONDS` | 기본 `60`. 최소 60초 간격으로 한 건씩 전송한다. 공급자의 발송 한도를 늘리는 설정이 아니다. |
| `OUTREACH_DAILY_LIMIT` | 기본 `25`, 설정 범위 1~100. 한국 날짜(Asia/Seoul) 기준이며 테스트 발송도 한도에 포함한다. |
| `APP_URL` | 수신거부 링크를 제공할 실제 공개 HTTPS 원점. 운영은 `https://pr-text.com`. |

네이버 메일의 환경설정에서 IMAP/SMTP 사용을 활성화하고, 네이버 계정의 2단계 인증과 애플리케이션 비밀번호를 준비한다. 일반 로그인 비밀번호를 소스·CSV·채팅·프런트엔드 환경변수에 넣지 않는다. SMTP 사용자 이름, 발신 주소와 회신 주소는 다른 주소로 바꿀 수 없다.

신규 `outreach` 마이그레이션을 적용해야 영속 연락처와 발송 큐를 사용할 수 있다. 먼저 격리된 PostgreSQL 17에서 기존 마이그레이션과 함께 재생하고 권한·동시성 검증을 완료한다. 기존 결제·전사 테이블의 권한과 상태를 변경하지 않는다. 운영 마이그레이션과 실제 SMTP 인증은 로컬 모의 검증과 별도 단계다.

CI의 `PostgreSQL 17 recovery and concurrency` 작업은 전체 마이그레이션을 재생하며 기존 작업·정산 회귀와 `scripts/validation/db-outreach.cjs`의 발송 큐 회귀를 함께 실행한다. 해당 스크립트는 운영 DB에서 실행하지 않는다.

활성화할 때는 Supabase Auth의 사용자 목록에서 지정한 관리자 로그인 이메일의 인증 상태와 UUID를 확인하고, 그 UUID만 서버의 `OUTREACH_ADMIN_USER_IDS`에 등록한다. 발신 이메일과 관리자 로그인은 별도이며 발신 주소가 같다는 이유로 관리자 권한을 주지 않는다. 신규 마이그레이션과 서버 설정을 반영한 뒤, 발송을 끈 상태로 관리자 접근·연락처·미리보기를 먼저 확인한다. 대기열이 없는 상태에서 발송을 켜고 본인 테스트를 확인한 다음 캠페인을 시작한다.

## 현재 검증 상태

2026-10-11 기준 Node.js 22 전체 테스트 510개와 프로덕션 빌드가 통과했다. 격리 PostgreSQL 17에서 기존 회귀 25개, 신규 큐 회귀 18개와 독립 검증 31개를 통과했다. 모의 HTTP·서비스 46개와 YouTube 응답 합성 검증 59개, 실제 Nodemailer의 로컬 TCP 중단·45초 제한 검증 3개도 통과했다.

브라우저에서는 로컬 모의 데이터로 로그인 복귀, 대상 선택, 만료 정보 갱신, 개인화 미리보기, 대기열·시작·일시정지, 권한 만료와 모바일 배치를 확인했다. 네이버 실제 인증·배달, 실제 YouTube API 요청, 운영 마이그레이션·서버 설정·배포는 별도로 진행해야 한다. 현재 검증을 운영 발송 준비 완료로 해석하지 않는다.

## 작업 흐름

1. 관리자 UUID를 설정하고 로그인한 뒤 `/admin/outreach`에 접속한다. 일반 회원과 미로그인 요청은 연락처·캠페인 API에 접근할 수 없다. 화면 주소를 아는 것만으로 권한이 생기지 않는다.
2. 웹예능, 배우 개인 채널, 기타 한국 채널 분류와 검색어로 후보를 조회한다. 검색 결과에서 공개 구독자 수 10만 이상을 걸러낸다. 한국으로 명시된 국가 정보를 확인하며, 국가 미기재 후보는 별도 근거를 확인한다. 검색 분류만으로 실제 웹예능·배우 채널임을 확정하지 않는다.
3. 업무용 공개 이메일과 그 출처를 직접 등록하거나 화면의 CSV 양식으로 최대 200행씩 가져온다. 가져오기는 전체 행을 검증하며, 이미 등록된 이메일의 동의나 수신거부 상태를 덮어쓰지 않는다.
4. 광고 수신 동의의 근거와 동의 일시를 별도로 입력한다. 공개 이메일의 출처는 동의 근거를 대신하지 않는다. 동의 미확인·철회, 한국 기반 미확인, 구독자 수 미확인·기준 미달, 오래된 채널 정보는 발송에서 제외한다.
5. 캠페인을 만들고 개인화 문안과 제외 사유를 미리보기에서 확인한다. `{{channelName}}`이 채널명으로 바뀐다. `(광고)` 제목, 코드밋의 실제 발신 정보와 무료 수신거부 안내를 붙인다. 미리보기 이후 연락처나 발송 조건이 바뀌면 다시 확인해야 대기열에 저장할 수 있다.
6. 큐가 없는 상태에서 발송 설정을 활성화하고 **본인 테스트 발송**으로 `codemeet@naver.com`에 먼저 확인한다. 테스트 수신자를 다른 주소로 지정할 수 없다. 화면에 테스트의 대기·접수·확인 필요 상태를 표시하며, 메일함에서 보낸 사람, 제목, 본문과 수신거부 흐름도 확인한다.
7. 확인한 캠페인을 대기열에 넣는다. 기본 방식은 저장 후 **순차 발송 시작**을 직접 누르는 것이며, 예약 방식은 지정 시각부터 자동으로 처리한다. 본문과 주소는 스냅샷으로 고정되며, 이후 문안 변경은 새 캠페인으로 진행한다. 같은 요청의 재시도는 추가 큐를 만들지 않는다. 전송을 일시정지한 뒤 다시 시작할 수 있다.

## 발송 기록의 의미

- `sent`는 SMTP 서버가 해당 메시지를 접수했다는 뜻이다. 상대방의 실제 수신·읽음·스팸함 여부를 확인하는 기능은 아니다.
- `uncertain`은 SMTP 전송 결과가 확실하지 않다는 뜻이다. 네트워크 단절이나 전송 도중 프로세스가 종료되면 이 상태로 보류하고 자동 재발송하지 않는다. 네이버 보낸메일함 등에서 확인해야 한다.
- 수신거부, 철회 또는 발송 자격 상실은 큐 등록 후에도 다시 확인하여 제외한다. 이미 SMTP 전송이 시작된 한 건을 소급 취소하지는 못한다.
- 같은 이메일은 같은 캠페인에서 중복 전송하지 않는다. 다른 캠페인이라도 최근 30일 안에 접수되었거나 전송 결과가 불확실한 주소는 다시 발송하지 않는다.
- 일일 한도와 간격은 데이터베이스의 전역 잠금으로 관리하여 여러 서버 인스턴스에서도 한 번에 한 건씩 발송한다. 여러 수신자를 한 메일의 To/CC/BCC에 묶지 않는다.

## 데이터와 수신거부

YouTube 검색은 공식 API의 채널 이름·국가·구독자 수를 조회한다. 이메일 주소는 이 API에서 제공되지 않으며 웹페이지 자동 수집, CAPTCHA 우회나 외부 주소록 구매를 사용하지 않는다. 검색은 검색어별 후보 조회이며 한국의 모든 10만 이상 채널을 빠짐없이 열거하는 기능이 아니다.

검색에서 가져온 채널 정보는 `youtube_api` 출처와 확인일을 보존한다. 30일을 넘긴 API 정보는 정기 작업으로 삭제하고 다시 확인할 때까지 발송에 사용하지 않는다. 일반 템플릿과 독립적으로 등록한 이메일, 동의·수신거부·발송 상태는 별도로 관리한다. 기존 수동 기록을 API 검색 결과로 갱신하면 API 출처로 관리하며, 이를 다시 수동 입력으로 바꾸어 보관 정책을 우회할 수 없다.

연락처와 관련 RPC는 서비스 역할만 접근할 수 있으며 RLS와 명시적 권한 제한을 함께 적용한다. 수신거부 토큰 원문, SMTP 비밀번호, 이메일 본문과 연락처를 서버 로그에 남기지 않는다. 수신거부 링크는 로그인 없이 확인 화면을 제공하고 제출 시 즉시 발송 대상에서 제외한다. 메일 스캐너가 링크를 미리 여는 GET 요청만으로 수신거부하지 않는다.

개인정보 열람·정정·삭제 요청은 `codemeet@naver.com`으로 접수한다. 관리자만 허용된 저장소에서 해당 주소의 연락처·개인화 스냅샷을 조회하고, 대기 발송을 제외한 뒤 필요한 삭제를 처리한다. 수신거부 주소를 다시 등록하거나 동의를 편의상 되살려 재발송하지 않는다. 정기적인 수신 동의 확인과 실제 발송의 적법한 근거 관리는 운영자가 확인한다. 이 기능은 법적 근거를 자동 판정하지 않는다.
