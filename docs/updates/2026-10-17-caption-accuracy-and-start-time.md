# 한국어 교정과 자막 시작 시간 보존

일반 한국어 변환에서 맞춤법을 고친 뒤 단어 시간 연결이 끊겨 앞 무음까지 자막이 표시되는 경로를 수정한다. 반복 발화 옆의 철자를 고칠 때 독립 반복을 삭제하는 응답도 보수적으로 차단한다.

## 교정과 반복

- 같은 청크의 앞뒤 문맥으로 대상과 행위를 확인하고 명백한 표기·동음 받아쓰기 오류만 교정한다. 실제 문맥이 불분명하면 원문을 유지한다.
- 반복 어절·구절의 경계·순서·횟수를 확인한다. 다른 단어 속 같은 글자가 삭제된 독립 반복을 대신하지 못한다. 손실이 감지된 줄은 원문으로 복원한다.
- 말투·사투리·추임새·숫자·단위·이름과 줄 순서를 보존한다. 현재 교정 모델과 폴백 정책은 유지하며 특정 단어를 일괄 치환하지 않는다.
- 모델의 원래 응답, 보호 검사 후 결과, 단어 시간 정렬 후 결과를 구분해 평가한다. 안전하게 원문을 남긴 교정 누락도 성공으로 세지 않는다.

## 단어 시간과 실제 파일의 시작

교정 전 원문 전체와 공급자 단어열·시각을 먼저 검증한다. 교정 뒤에는 제한된 한글 철자 편집의 유일한 단조 경계 대응만 사용한다. 긴 문장 내부도 검증된 단어 시작에 맞추며, 대응이 모호하면 검증된 원문 큐를 보존한다. 원래 단어 문자열이나 시간을 교정문에 맞춰 덮어쓰지 않는다.

PCM/IEEE-float WAV에서는 원래 채널과 샘플 정밀도로 앞부분의 모든 샘플이 정확히 0인지 확인한다. 이 근거가 있으면 첫 비영 샘플 이전에 자막이 시작하지 않도록 별도 하한을 전달한다. 작은 비영 샘플도 소리로 인정하며 음량 임계값·VAD·다운믹스는 사용하지 않는다. 지원하지 않는 형식, 손상된 파일, 전체 무음에는 시작 근거를 만들지 않는다. 대사 삭제나 임의 끝 시간 생성으로 무효 구간을 감추지 않는다.

일반 단일과 사람별 묶음의 파일별 0초 원점과 앞 무음은 유지한다. 단일의 1초 이내 간격 표시는 이전 자막의 끝만 다음 시작까지 유지하며, 묶음의 ZIP·개별·기록 내보내기는 기존 발화 끝을 유지한다. 영어와 다화자의 기존 시간 정책은 유지한다.

내보내기 때 대사 시작은 SRT의 1ms, ASS의 10ms 단위로 올림한다. 이전 반올림으로 생길 수 있던 시작의 앞섬을 막으며 fps 배율을 적용하지 않는다. 끝은 기존 반올림을 유지하고, 일반 단일의 간격 유지가 적용된 끝은 다음 시작과 같은 표시 시각으로 맞춘다. 형식 정밀도보다 짧은 대사는 역전 없이 같은 시작·끝 시각이 될 수 있다.

## 구현 검증

- Node.js 22 전체 회귀 591/591 통과, 건너뜀 0. 프런트엔드 빌드 77개 모듈 및 변경 공백 검사 통과.
- 기존 단일·묶음의 인증·소유권·편집·기록, 개별 SRT/ASS와 ZIP, 파일별 시작 무음·공통 0초 원점·5000행 compact, 영어·다화자 및 단일 표시 유지 제외 정책을 합성 데이터와 모의 API로 검증했다. 운영 DB·결제·고객 계정은 사용하지 않았다.
- 실제 AI의 과거 반복 손실 응답 3건은 새 보호 검사에서 원문으로 복원됐다. 올바른 반복 보존 교정 후보는 통과했다.

## 실제 AI 평가

현재 제품 교정 함수와 기본 모델 `gpt-5.6-luna`를 사용했다. 최종 응답의 모델 필드도 동일했고 폴백·실패·응답 불명확은 0이었다. 호출 전 정답을 동결하고, 원시 응답·보호 검사 후 결과·단어 정렬 후 결과를 별도로 확인했다. 최종 프롬프트의 합성 93문장 × 3회와 고립형 진단 3회를 합쳐 282행 관측이며, 282개의 서로 다른 문장이라는 뜻은 아니다.

| 평가 조건 | 교정 성공 | 보존 대상 |
| --- | --- | --- |
| 기존 73문장 × 3회 및 고립형 진단 3회 | 103/105 | 엄격 일치 115/117, 서식 검수 후 117/117 |
| 새 독립 20문장 × 3회 | 27/27 | 33/33 |
| 합계 | 130/132 | 엄격 일치 148/150, 서식 검수 후 150/150 |

`나물을 묻혀서 → 나물을 무쳐서`는 청크 3/3과 고립형 3/3에서 교정됐다. 반복이 있는 교정 문장도 독립 반복 횟수를 보존했다. 보존 대상의 엄격 불일치 2회는 `네네네 → 네 네 네`의 띄어쓰기였고, 말투·의미·반복 횟수 손실은 발견되지 않았다. 앞줄에 음식 문맥이 있는 다른 문장의 안전한 미교정 2회는 그대로 실패로 기록했다. 전체 처리 경로에서 교정을 추가로 되돌리거나 검증된 단어 경계보다 시작을 앞당긴 경우는 0이었다.

위 표는 최종 교정 HTTP 15회에서 나온 관측이다. 개발 중 중간 프롬프트 결과를 합산해 성적을 높이지 않았다. 같은 문장 반복 측정과 작은 합성 표본이므로 실제 모든 음원의 무오류를 보장하지 않는다.

## 생성 음성의 실제 전사와 시작 시간

AI로 생성한 한국어 음성 두 개를 원래 PCM 바이트 그대로 조합해 단일 파일과 사람별 WAV 두 파일을 만들었다. Whisper 실제 전사 3회와 최종 제품 교정 실제 호출 3회를 실행했다. 고객 음성이나 고객 대사는 사용하지 않았다.

| 합성 파일 | 검증한 첫 비영 PCM 시각 | 원시 Whisper 첫 구간 시작 | 최종 SRT 첫 대사 시작 |
| --- | --- | --- | --- |
| 단일 | 2.000초 | 2.220000029초 | 2.221초 |
| 사람 A | 2.000초 | 1.620000005초 | 2.000초 |
| 사람 B | 10.000초 | 9.579999924초 | 10.000초 |

최종 내부 결과·SRT·ASS 모두 검증한 첫 비영 PCM보다 먼저 시작하지 않았다. A/B의 원시 전사에는 약 380/420ms 앞섬이 있었으며 별도의 시작 하한으로 제한했다. B에는 길이 0인 단어가 있어 완전한 단어 정렬을 주장하지 않고 대사를 보존하는 구간 폴백을 사용했다. 단일 파일에는 공급자 단어 시작의 약 220ms 지연이 남는다. 완전무음 하한 검증은 이 지연이나 잡음 속 실제 음소 시작을 해결하는 근거가 아니다.

## 확인 범위

단어 시간은 음성 인식기의 추정값이다. 디지털 완전무음의 첫 비영 샘플도 사람이 표시한 음소 시작 정답은 아니다. 자연 잡음이 있는 음원, 단어 정보가 없는 과거 기록, 불완전 단어, 긴 수동 편집의 내부 싱크를 저장된 정보만으로 정확하게 복구한다고 보장하지 않는다. 추가 음성 정렬이나 재변환이 필요할 수 있다.

실제 사용자 문제 파일과 Premiere 가져오기는 별도 검증 대상이다. 이번 검수는 동결된 합성 텍스트의 실제 AI 평가, 생성한 한국어 음성의 실제 Whisper 전사, 저장 응답 재사용, 단일·묶음 내보내기 회귀를 구분해 기록한다. API 키·고객 대사·고객 음원은 검증 문서에 포함하지 않는다.

검증 근거는 로컬 `.tools/qa-korean-live-eval/`의 최종 동결 평가·독립 전체 처리 검수와 `.tools/qa-caption-accuracy-fix/`의 생성 음성·전사·교정·전체 회귀 기록에 보존한다. 배포의 정확한 커밋과 운영 검수 결과는 해당 PR 및 로컬 배포 기록에서 별도로 확인한다.
