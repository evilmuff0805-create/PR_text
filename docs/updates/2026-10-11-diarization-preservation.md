# PR_text 업데이트 — 다화자 대사 누락 방지

기록일: 2026-10-11, 한국 시간 기준.

## 범위

사용자는 기존 전사 서비스를 유지하면서 누락·화자별 자막 분리를 우선하기로 선택했다. 이번 변경은 화자 수 직접 지정, 새 전사 공급자, DB·정산·작업 상태를 추가하거나 변경하지 않는다.

## 재현한 문제와 수정

- 같은 시각에 시작한 세 화자의 큐가 겹침 정규화 과정에서 0초로 잘려, SRT·ASS에 마지막 대사만 남았다. 같은 시작 시각의 큐는 각각 보존하고 다음의 서로 다른 시작 시각에만 기존 겹침 정규화를 적용한다. 긴 문장 분할 뒤에 생기는 같은 시작 시각도 처리한다.
- 빈 큐와 길이 없는 큐가 실제 대사의 시간을 자르던 문제를 막기 위해 이들을 시간 정규화 전에 제외한다.
- 교정 결과의 줄 수가 맞아도 공백 한 줄이 짧은 응답을 지울 수 있었다. 공백, 순수 글자 삭제·추가, 짧은 반복 음절·구절의 횟수 변화를 감지하면 해당 줄만 원문으로 되돌린다. 다른 부분의 맞춤법 교정과 반복 축약이 동시에 일어나는 경우도 검사한다.
- 다화자 M4A도 무조건 모노·16kHz·32kbps MP3로 바뀌고 있었다. 지원하는 M4A는 원본을 우선 전송하며, 크기·형식 때문에 변환이 필요할 때 다화자는 128kbps를 사용하고 채널 수·샘플링 주파수를 모노·16kHz로 강제하지 않는다. MP3가 지원하지 않는 입력 형식은 인코더가 조정할 수 있다.
- 브라우저의 대용량 WAV 최적화는 모든 채널을 평균해, 반대 위상의 스테레오를 완전한 무음으로 만들 수 있었다. 모든 채널을 유지하는 16bit PCM으로 바꾸고, 150MiB 안에서 원본 주파수(최대 48kHz)를 우선 사용한다. 크기 때문에 필요한 경우에만 32/24/16kHz로 낮추며, 마지막 프레임이나 시간을 잘라서 한도에 맞추지 않는다.

일반 전사의 서버 32kbps 변환 정책, 0.3초 짧은 구간 병합, 영어 단어 시간 처리는 유지한다. 브라우저 WAV의 채널 보존은 모드 선택 전에 적용된다.

## 검증

- 수정 전 새 대사 보존 회귀 7개 중 5개가 실패해 누락을 재현했다. 이후 혼합 맞춤법·반복 변화, 긴 자막 분할 경계, 다음 발화 경계까지 회귀를 추가했다.
- Node.js 22.23.3에서 `npm test`: **374개 통과, 실패·건너뜀 0개**.
- `npm run build`: 성공, 68개 모듈 변환. `git diff --check`: 성공.
- 독립 QA가 세 사람의 대사, 짧은 응답, 같은 시작 시각, 긴 문장 분할, 공백·반복 교정, 입력 불변성을 별도로 확인했다.
- FFmpeg 9.0.2로 아래 합성 음원 실변환을 확인했다. 외부 전사 API를 실제 호출하거나 고객 음원을 사용하지 않았다.

| 단계 | 채널·주파수 | 길이 | 파일 크기 |
| --- | --- | --- | --- |
| 반대 위상 스테레오 WAV 원본 | 2채널, 48kHz | 1,200초 | 230,400,044B |
| 브라우저 WAV 최적화 | 2채널, 32kHz | 1,200초 | 153,600,044B (150MiB 이하) |
| 실제 다화자 저장용 MP3 압축 | 2채널, 32kHz, 128kbps | 1,200초 | 19,201,580B (25MiB 이하) |

압축 후 양쪽 채널 RMS는 각각 약 0.26857이었다. 같은 합성 음원을 기존 일반 변환의 모노 정책으로 처리하면 RMS가 0이 되어 상쇄됨을 확인했다. 실패 시 임시 파일 정리와 실인코딩 후 모의 SDK 취소의 `ABORTED` 분류도 확인했다. 인코더 실행 중 즉시 취소를 검증한 결과는 아니다.

샌드박스에서는 로컬 모의 HTTP 연결과 Vite의 `realpath` 호출이 제한돼 첫 전체 실행이 실패했다. 같은 명령을 해당 제한 없이 재실행해 위 결과를 확인했다.

## 남은 한계와 반영 상태

- 실제 음원에서 전사 정확도나 동일 인물 판별이 개선됐는지는 별도 비교가 필요하다. 공급자가 애초에 누락하거나 같은 화자로 잘못 묶은 대사를 이 코드가 음성 분석으로 복원하지는 않는다.
- 현재 사용하는 [OpenAI 전사 API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)의 문서에는 화자 수를 숫자로 지정하는 옵션이 없다. 화자 수 직접 지정과 인물 과분류 제어는 사용자 선택에 따라 다음 단계로 남겼다.
- 같은 시작 시각의 큐는 분리된 항목으로 중첩될 수 있으며, 편집 프로그램별 표시 방식은 다르다. 서로 다른 시작 시각의 기존 겹침 자르기는 유지한다. SRT의 밀리초·ASS의 센티초보다 짧은 발화는 형식의 시간 해상도 한계가 있다.
- 교정 보호는 보수적인 규칙이며 모든 의미 변경을 판별하지 않는다. 특히 반복 단위 자체의 교정은 원문 보존을 우선할 수 있다.
- 운영 배포와 실제 고객 음원 검증은 수행하지 않았다. 검토용 PR의 원격 CI 결과는 로컬 검증과 별도로 확인한다.
