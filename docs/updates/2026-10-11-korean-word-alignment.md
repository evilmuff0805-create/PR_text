# PR_text 업데이트 — 일반 한국어 발화 시간 정렬

기록일: 2026-10-11, 한국 시간 기준.

## 원인과 변경

기존 일반 한국어는 구간별 시간만 요청하고 긴 문장의 내부 시간을 글자 수에 비례해 나눴다. 따라서 의미 단위 분할을 고쳐도 말하는 속도나 쉼에 맞는 분할 시간을 알 수 없었다. 짧은 응답을 교정 전에 다음 구간과 합치면서 단어 정보도 뒤 구간의 것으로 덮이는 경로가 있었다.

일반 한국어에도 기존 `whisper-1`의 `verbose_json`과 `timestamp_granularities: ['segment', 'word']`를 사용한다. OpenAI 공식 문서는 이 옵션과 단어 타임스탬프 생성 시 추가 지연 가능성을 설명한다. 전사 공급자·교정 모델은 바꾸지 않는다. [OpenAI 공식 전사 API 문서](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)

- 맞춤법·띄어쓰기 교정 후 전체 글자·숫자를 NFC 기준으로 원래 단어열과 대조한다. 공백·문장부호 및 단어 토큰화 차이는 허용하며 실제 글자 변경, 빠진 단어, 달라진 반복을 임의로 정렬하지 않는다.
- 유효한 구간은 기존 28자 의미 분할 계획을 우선하고 실제 단어 경계에서만 나눈다. 각 큐는 첫 단어 시작에서 나타나 마지막 단어 끝에서 끝난다. 0.3초를 넘는 단어 사이 쉼도 분리하며, 짧은 발화를 가독성 하한 때문에 늘리지 않는다.
- API 단어 하나에 여러 어절이 들어 있어 의미 경계가 그 안에 있으면 주변의 안전한 단어 경계를 찾는다. 28자 조건을 만족할 경계가 없거나 시간 정보가 불완전하면 원래 구간을 유지하고 기존 내보내기로 폴백한다. 단어 내부 시간을 새로 추정하지 않는다.
- 단어 정보가 있는 짧은 한국어 응답은 교정 전 병합하지 않는다. 공급자가 따로 나눈 종속 서술어는 양쪽 단어 정보가 완전하고 실제 발화 간격이 0.3초 이내일 때만 다시 계획한다. 긴 쉼이나 다른 화자와는 합치지 않는다.
- `timingSource: 'word'`를 보존해 내보내기의 기존 글자 기반 꼬리 재결합이 정렬을 덮지 않게 한다. 원래 단어 배열은 결과에서 제거한다.

## 저장과 재다운로드

새 변환은 정렬된 구간을 저장하고, 화면·편집·재다운로드는 해당 시작·끝 시간을 유지한다. 기존 한도 안의 원본이 분할 후 5,000행을 넘으면 원본 행 수로 저장하면서 계산된 `wordAlignedCues`를 `[시작, 끝, 텍스트]` 튜플로 보존한다. 숫자의 정밀도를 줄이지 않고 반복 JSON 키를 생략해 긴 결과의 크기를 줄인다. 내보내기가 이 큐를 현재 텍스트와 시간 범위에 다시 대조하므로 행 한도를 늘리거나 자막 시간을 포기하지 않는다. 종속 꼬리 병합도 행별 10,000자와 전체 100만 자 한도를 넘기지 않으며, 초과 시 각각의 발화를 별도로 보존한다.

JSON 저장·복원 뒤에도 메타데이터를 보존한다. 수동으로 글자를 바꿔 보관된 타임스팬과 맞지 않으면 기존 시간 범위로 폴백한다. 수동 편집은 음성 인식 재실행이 아니며, 긴 문장으로 바꾼 경우의 내부 시간 정렬은 보장하지 않는다.

## 검증

- 익명 단어 타임스탬프로 기존 글자 비례 분할, 앞뒤 여백 포함과 짧은 응답의 무음 병합을 수정 전에 재현했다.
- 모듈 단위 검사와 교정 → 정렬 → SRT·ASS, 짧은 응답, 종속 꼬리, 교정 실패·글자 변경 폴백, 자동 한국어 판단, 청크 오프셋, JSON 복원·편집·재다운로드, 5,000행·10,000자·전체 100만 자 한도 회귀를 추가했다. 숫자·약자 내부의 마침표를 손상하는 분할과 잘못된 시간 자료형도 확인했다.
- 독립 QA에서 Node.js 22.23.3 전체 테스트 437/437 통과(실패·건너뜀 0), 프로덕션 빌드 69개 모듈 성공, 기본 git diff --check 성공. 검사 전후 소스·테스트 해시도 동일했다.
- 독립 사례 31개와 무작위 입력 1,500개에서 실패 0. 정렬 결과 19,374큐 및 처리·SRT·ASS를 거친 2,699큐의 원문·순서·시간 보존을 확인했다. 안전하지 않은 단어 내부 경계 182개는 원본 구간으로 폴백했다.
- 6,000큐를 300행으로 저장한 256,419B JSON의 복원·편집·내보내기를 로컬 HTTP와 DB 모형으로 확인했다. 요청 본문은 정확히 50MiB에서 허용되고 1B 초과 시 413으로 차단됐다. 실제 DB 검증은 아니다.
- 전체 100만 자를 채운 꼬리 병합 반례에서 1,000행·100만 자·36,500큐로 기존 검증기를 통과했다. 별도의 극단 합성 입력 100만 큐는 100행·46,136,168B로 50MiB 안에 보존했다. 약 167시간 분량의 인공 입력이며 실제 음원 처리 성능을 대표하지 않는다.

## 적용 범위와 한계

- 기존 다화자·영어 처리, 시작 안내, 과금·크레딧·DB 스키마와 무음 관측 정책은 유지한다. 음량 임계값으로 작은 목소리를 삭제하지 않는다.
- 단어 타이밍은 음성 인식기가 반환한 추정치다. 실제 고객 음원과 프리미어 프로 2026의 프레임별 정렬은 검증하지 않았으며 완전한 일치를 보장하지 않는다.
- SRT는 1밀리초, ASS는 1센티초 단위로 기존 방식대로 반올림한다. 그보다 짧은 발화가 같은 표시 시각으로 반올림될 수 있으며 무음을 덧붙여 이를 감추지 않는다.
- SRT는 밀리초 절대시간을 저장한다. 29.97fps 스냅, 고정 프레임 간격 또는 DF/NDF 시간 재배율을 추가하지 않았다. 프리미어 시퀀스 설정과 구분한다.
- 단어 시간 정보가 저장되지 않은 과거 기록은 재다운로드만으로 새 정렬을 복원할 수 없다. 이 개선은 새 일반 한국어 변환부터 확인한다.
- 실제 외부 전사 API·고객 음원·운영 DB 호출과 운영 배포는 수행하지 않았다. 원격 CI 결과도 로컬 검사와 별도로 확인한다.
