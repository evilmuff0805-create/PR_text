# 일반 한국어 자막 경계와 검토 흐름

일반 전사와 교정 모델, 말투·반복·수치 보호를 유지하면서 긴 오디오의 분할 경계와 실제 단어 경계의 문장 분할을 보완한다. 이 변경은 검토용이며 운영 배포는 사용자 결과 확인 후 별도 승인한다.

## 전사 조각의 소유 경계

이전 구현은 공급자 세그먼트의 끝으로만 조각 소유권을 정했다. 다음 조각의 긴 세그먼트에 앞 조각 문맥이 포함되면 두 결과가 겹치고, 내보내기에서 앞 자막이 매우 짧게 잘릴 수 있었다.

일반 한국어의 경계를 걸치는 세그먼트는 텍스트 전체와 유일하게 일치하는 완전한 공급자 단어열이 있을 때만 어절과 시간을 함께 나눈다. 경계를 걸친 단어는 끝 시각에 따라 한 조각에 배정하며 단어 자체를 자르지 않는다. 문자열 반복만으로 중복을 삭제하지 않는다. 응답 간 단어 추정이 충돌하거나 근거가 불완전하면 원래 폴백과 검토 표시를 유지한다. 이 근거는 공급자 추정이며 실제 음소 정답을 뜻하지 않는다.

## 의미 분할과 교정

글자 기반 분할과 실제 단어 경계 재계획은 같은 한국어 의존 구문 비용을 사용한다. 의문어·서술부, 부사격 표현·관형절의 분리를 줄이되 28자, 0.3초 초과 쉼, 다른 입력·화자 경계는 유지한다.

교정의 30행 청크 앞뒤 최대 3행은 읽기 전용 문맥으로 전달한다. 수정 대상 행을 JSON의 `targetLines`로 분리하고 출력 행 수·순서와 기존 보존 가드를 검증한다. 기본 교정 모델과 지원 오류 시 폴백 정책은 동일하다.

거부된 교정과 단어 대응 실패는 현재 텍스트를 유지하고 후보·사유를 `subtitleReview`로 분리한다. 전체 후보를 여러 분할 큐에 복제하지 않도록 필요한 경우 기존 `wordAlignedCues` 형태의 원행을 보존한다.

## 제한된 오디오 재검수

기존 전사 모델로 일반 한국어의 비정상 압축 후보만 재측정한다. 기본 자동 선별은 5글자 이상 대사가 0.3초 미만인 원본 세그먼트이며, 최대 3개 창·창당 20초·전체 60초다. 정상적인 짧은 응답은 이 이유만으로 재요청하지 않는다. 각 추가 공급자 요청은 SDK 재시도 없이 한 번만 실행한다.

유일한 전체 텍스트 일치와 유효한 단어 시간, 이웃 구간 비침범을 확인한 경우에만 시간을 대체한다. 다른 문구는 기존 대사를 변경하지 않고 검토 후보로만 제안한다. 실패·불일치도 대사를 버리거나 임의 연장하지 않는다. 서비스의 명시적 검토 창 옵션은 같은 한도를 적용한다. 전사 서비스의 선택적 용어 목록은 UTF-8 192바이트 이내이며 기본 요청에는 힌트를 추가하지 않는다.

## 결과 화면

단일·묶음 공통 편집기는 보존 문구, 현재 편집 문구, 정정 후보, 시간 범위와 사유를 보여준다. 후보 입력은 명시적 적용 전까지 현재 텍스트·서버 저장과 분리한다. 사용자가 확인한 문구도 발화 싱크는 미확인 상태로 표시한다. 텍스트를 바꾸면 기존 단어 대응을 다시 검증하며, 수동 교정 뒤의 내부 시간을 자동 정답으로 설명하지 않는다.

원본은 선택적으로 다시 연결해 브라우저의 로컬 URL로만 재생한다. 서버에 업로드하지 않으며 계정·파일 전환과 연결 해제 시 정리한다. 구간 재생은 앞뒤 0.5초를 포함한다. 정정 기억은 기본 해제이며 현재 창·파일 범위의 명시적 후보 재사용만 지원한다.

`subtitleReview`는 편집 검토용 데이터다. 서버 권한이나 실제 음성 정답의 증명으로 사용하지 않는다. 기존 JSONB 편집 저장 계약을 사용하며 DB 스키마·크레딧·작업 상태는 변경하지 않는다.

## 유지되는 내보내기 계약

- 일반 단일의 1초 이하 빈 구간 표시 유지는 최종 분할 뒤 표시 끝에만 적용한다.
- 묶음·개별 묶음·기록 재다운로드는 각 파일의 원점·발화 끝을 보존한다.
- SRT 시작 1ms·ASS 시작 10ms 올림, 0~2초 안내, 한 줄·28자, 기존 다화자·영어 경로를 유지한다.
- 짧음·읽기 속도·겹침 잘림 표시는 검토 신호이며 최소 표시 시간 강제나 조기 시작 보정이 아니다.

## 검증과 한계

고정한 실제 공급자 응답의 기존·개선 처리와 별도의 실제 신규 전사 호출을 구분한다. 사용자 확인 문구, 부분 재전사 후보, 자동 교정 결과와 수동 확인 적용본도 별도 집계한다. 새 공급자 응답에서 이미 달라진 구간을 코드 성능 향상으로 계산하지 않는다.

합성 보존·반례 테스트, 최대 5개 ZIP의 독립 파서, 실제 로컬 HTTP 및 브라우저 검증을 함께 사용한다. 공급자 추정과 파형·표시 경계 검사는 직접 청취 또는 모든 단어 시작·끝 정확도의 증명이 아니다. 고객 자료와 정답은 제품 코드·공개 문서에 넣지 않고 소유자의 로컬 비교 자료로만 제공한다.

2026-10-25 검토본의 Node22 전체 테스트는 668/668(건너뜀 0), 빌드는 78개 모듈로 통과했다. 실제 브라우저에서 후보 적용·저장 뒤 같은 편집기 유지, 새로고침의 전체/구간 문구·확인 상태 복원, 단일 SRT와 최신 편집본을 포함한 5개 ZIP 다운로드를 확인했다. 검토창 열 너비와 저장 후 복원 문제는 이 검수 중 재현·수정했다.

별도 보존 문장 16개는 기존·개선 모두 통과했다. 고정 음원의 비정상적으로 압축된 긴 대사는 동일 공급자 응답에서 2개에서 0개가 됐다. 특정 내용 오인식은 전체 자동 교정에서 여전히 남았으며, 같은 기존 모델의 부분 재전사 후보와 사용자 확인 적용본을 분리해 보고했다. 자동 정확도 전반의 향상이나 실제 음소 싱크를 보장하는 결과로 확대하지 않는다.
