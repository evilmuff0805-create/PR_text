# 사람별 오디오 최대 5개 일반 변환과 SRT ZIP

사람별로 녹음한 오디오를 최대 5개 선택해 일반 변환하고, 인물마다 별도의 SRT를 ZIP으로 받는다. 기존 단일 파일 변환과 다화자 변환은 유지한다. 묶음 내부에서 화자를 다시 분석하거나 여러 사람의 음성이 섞인 파일을 분리하지 않는다.

## 동작

- 최초 접수 전에 파일 이름에서 만든 인물 이름과 순서, 공통 언어를 수정한다. 큰 WAV 준비와 업로드를 파일별로 순차 진행한다.
- 모든 파일을 접수하고 서버가 길이를 확인한 뒤 총 차감 시간을 보여준다. 변환 시작을 누르면 한 트랜잭션에서 자식 파일별 분 단위 올림·최소 1분을 예약한다. 부모 묶음에는 별도 예약이 없다. 한 파일이라도 예약에 실패하면 전체가 롤백된다.
- 묶음당 한 파일을 처리하며 기존 긴 파일 내부 청크 동시 처리 한도는 유지한다. 접수된 작업을 새로고침·로그인 복귀 후 확인하고, 확정 실패한 파일만 새 시도로 재접수한다. 완료·체크포인트가 있는 파일은 다시 전사하지 않는다.
- 편집 초안을 사용자와 기록별로 분리하고 인물 전환·ZIP 생성 전에 저장을 마친다. 최신 저장된 편집본으로 파일별 SRT를 생성한다. 일부 실패 시 완료된 개수를 명시한 부분 다운로드를 제공한다.
- 각 SRT의 절대 밀리초 시간과 앞부분 무음을 보존한다. 다른 파일의 동시 발화를 합치거나 자르지 않고, 첫 발화를 0초로 당기거나 29.97fps로 재배율하지 않는다. 원본 파일들이 같은 영상의 0초에서 시작해야 한다.
- 각 SRT에 기존 0~2초 시작 안내를 정확히 한 번 넣으며 실제 초반 대사는 유지한다. 인식 대사가 없는 파일은 검토 필요로 표시하고 안내만 있는 SRT를 제공한다. 작은 목소리를 자동 삭제하지 않는다.
- 계정당 활성 묶음 최대 1개, 기존 단일 작업과 묶음을 합쳐 활성 접수 단위 최대 3개를 유지한다. 업로드 전 묶음도 진행 작업으로 세어 기존 계정 삭제 정책을 적용한다.

## 검증과 승인

- Node.js22.23.3 전체 **534/534 통과**, 실패·건너뜀0. production build77모듈과 공개 HTML5종 생성, CRLF diff 검사 통과.
- 독립 PostgreSQL17.11 전체 마이그레이션 재생: 기존 작업16·동시성9·신규 묶음22 검증 통과. 개발팀의 별도 신규 DB17검증도 통과했다. 예약 전체 롤백, 멱등성, 원장/만료, 취소·완료 경쟁, 공유 작업 슬롯, 오래된 작업자 차단, 기존 경로 우회 방지와 계정 삭제를 확인했다.
- 독립 실제 HTTP/서비스/작업자7흐름, 실제 JSX Provider VM4흐름 및 UX 후속3흐름 통과. 파일별 최신 편집 ZIP과 소유권, 재시도, 응답 유실, 부분 성공을 확인했다.
- 독립 Node ZIP·합성 PCM·청크 오프셋6회귀와 Python 표준 ZIP41검증 통과. 한국어 파일명, Unicode 경계, CRC, 큰 자막의 압축 단어 시간, 첫2초 대사와 파일 간 동시 발화를 확인했다.
- 본부장 실제 IAB에서 5개 선택·6번째 차단, 이름/순서, 접수 후 새로고침, 시작 전 미차감, 4/5 부분 ZIP, 줄 수 오류의 다운로드 차단, 인물 전환 저장·초안 격리를 확인했다. 실패 파일 하나만 재선택해 1분 재예약 후 5/5 완료했고, 기존 단일 일반 변환도 정상 완료했다. 모바일 document/scroll 너비384px로 가로 넘침이 없었다.
- 본부장 구현 완성 승인. 검증용 로컬 UI·PostgreSQL 서버를 종료하고 근거를 보존했다. 기존 미커밋 작업 기록은 그대로 보존하며 이번 PR에서 제외했다.

검증은 합성 음원·모의 ASR·격리 DB를 사용했다. 실제 고객 음원, 유료 전사, 운영 DB와 Premiere Pro2026 가져오기는 검증하지 않았다. 음성 인식기가 추정한 시간을 실제 오디오의 프레임 정답으로 보장하지 않는다. API 응답이 체크포인트 저장 전에 유실된 경우 외부 전사의 정확히 한 번 실행을 보장할 수 없으며, 고객 예약·정산과 저장된 결과의 재처리를 방지한다.

검증 근거는 로컬 `../.tools/qa-person-audio-batch/`와 `../.tools/qa-pr-text-batch-artifacts/`에 있다. 전자에는 최종 전체 테스트·빌드, 실제 브라우저 화면 및 최신 편집 ZIP 대조를, 후자에는 독립 QA·개발팀 검증·소스 해시·소유 PG 서버 종료 기록을 보관한다.

## 반영 범위

운영 DB 변경과 배포는 실행하지 않았다. 새 코드의 정리 작업이 신규 RPC를 사용하므로 **코드 배포 전에** `20261017014800_person_audio_batches.sql`까지 적용해야 한다. `TRANSCRIPTION_BATCHES_ENABLED`는 신규 묶음 접수만 제어하고 기존 단일 접수 설정은 유지한다. 설정을 꺼도 기접수 작업의 처리와 정리는 이어간다.

검토 PR과 원격 CI 결과는 로컬 구현 검증과 구분한다. 사용·운영 절차는 [사람별 오디오 묶음 안내](../person-audio-batches.md)에 정리했다.
