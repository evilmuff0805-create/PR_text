# PR_text 업데이트 — 일반 자막 의미 분할과 시간 겹침

기록일: 2026-10-11, 한국 시간 기준.

## 재현과 수정

일반 한국어는 내보내기 단계에서 28자 이내의 뒤쪽 어미를 먼저 찾았다. 이 방식은 조건절 뒤의 짧은 서술어만 다음 자막에 남기는 경우가 있었다. 익명 동형 문장으로 재현한 예시는 아래와 같다.

| 구분 | 첫 자막 | 다음 자막 |
| --- | --- | --- |
| 이전 | 편안하게 생각이 흐르는 대로 경험을 통해 떠올리면 | 됩니다 |
| 수정 | 편안하게 생각이 흐르는 대로 | 경험을 통해 떠올리면 됩니다 |

- 일반 한국어의 어절 경계를 함께 평가해 의존 구문, 부정·보조 서술어, 인용형, 관형어·의존명사와 짧은 꼬리 구절을 고려한다. 28자·한 줄을 유지하며 공백 정규화 외의 대사와 반복 표현을 보존한다.
- 분할 계획은 원본 구간마다 한 번 계산한다. 긴 문장에 대해 남은 부분 전체를 매번 다시 계획하지 않는다.
- 공급자가 종속 서술어를 별도 구간으로 나눈 경우에는 명확한 앞 구문과 기존 일반 병합 한도인 0.3초 이내 간격일 때만 다시 묶어 분할한다. 원래 문장부호·완결 어미, 화자 라벨, 공급자 단어 타이밍을 확인한다. 이 일반 경로는 짧은 무음을 포함할 수 있다.
- 같은 시작 시각의 일반 원본 구간은 입력 순서대로 묶고, 다음의 서로 다른 원본 시작 시각에서 시간 범위를 자른 뒤 분할한다. 원문 삭제·순서 역전과 분할 후 조각이 다른 구간에 끼어드는 문제를 막는다. 범위를 뒤로 늘리는 방식으로 겹침을 처리하지 않는다.
- 화자 라벨이 있는 다화자는 앞선 대사 보존 정책을 유지한다. 일반 영어의 단어 시간 처리와 전사·교정·정산 경로도 유지한다. 새 분할은 SRT·ASS 다운로드와 과거 기록 재다운로드에 적용된다.

## 29.97fps 확인 결과

기존 앱에는 29.97fps 기본값이나 fps 요청 필드가 없었다. SRT는 `시:분:초,밀리초` 형태의 절대시간을 저장하며 fps 메타데이터를 포함하지 않는다. 프리미어 시퀀스의 프레임레이트 설정과 구분해야 한다. [미 의회도서관의 SRT 형식 설명](https://www.loc.gov/preservation/digital/formats/fdd/fdd000569.shtml)

Adobe는 NTSC 29.97fps를 `30000/1001`로 표현한다. 이번 변경은 SRT 초값에 프레임레이트 재배율을 적용하지 않으며, 임의의 프레임 공백이나 프레임 스냅도 추가하지 않는다. 실제 편집기 가져오기 동작을 확인하지 않은 상태에서 시간이 달라지는 것을 피한다. [Adobe XMP 시간 자료형](https://developer.adobe.com/xmp/docs/xmp-namespaces/xmp-data-types/)

구간별 편집 화면은 0.1초 표시에서 `MM:SS.mmm` 표시로 바꿔 작은 간격을 확인할 수 있게 했다. 두 다운로드 화면에는 SRT 시간 형식과 원본 영상에 맞는 시퀀스 설정 안내를 추가했다.

## 검증

- 새 일반 내보내기 회귀 10개 중 수정 전 6개가 실패해 분할·겹침·순서 문제를 재현했다.
- 최종 검증: Node.js 22에서 전체 테스트 **400/400 통과**, 실패·건너뜀 0. 프로덕션 빌드 성공, 69개 모듈 변환. 기본 `git diff --check` 통과.
- 공개 회귀에는 익명 동형 문장을 사용했다. 사용자 원문은 저장소에 저장하지 않고 로컬 임시 검증에서 요청한 두 구절 분리를 확인했다.
- 독립 QA: 이전 분할 계획과 6,042개 경우의 출력이 완전히 동일했다. 무작위 원본 2,000개에서 SRT·ASS 총 7,970개 큐의 원문·순서·28자·한 줄·일반 비중첩·입력 불변성을 확인했다.
- 24/25/30/23.976/29.97/59.94fps 합계 347,200프레임의 밀리초 왕복 계산과 5,000개 양수 간격 큐에서 오류 0을 확인했다. 이는 수학·파일 검증이며 프리미어의 가져오기 구현 검증은 아니다.
- 허용 최대 100만 자가 같은 시작 시각으로 입력된 합성 사례도 확인했다. 도달 가능한 어절 시작과 초과 길이 어절 내부만 계획해 띄어쓴 사례가 4.34초에서 1.16초로 줄었다(RSS 약 163MiB, 해당 로컬 환경). 무공백 사례도 원문 100%와 길이 제한을 보존했다. 실제 서비스 응답 시간 보장은 아니다.
- PR 원격 CI 결과는 이 로컬 검증과 별도로 확인한다.

## 한계와 반영 상태

- 규칙 기반 분할이며 모든 문장의 의미를 이해하는 형태소 분석은 아니다. 구문 자체가 28자를 넘으면 분할이 필요하다.
- 단어 타이밍이 없는 한국어의 내부 분할 시간은 글자 수 비례 추정이다. 같은 시작 시각의 일반 구간 순서는 입력 순서를 사용하며 실제 동시 발화 순서를 분석하는 기능은 아니다.
- 사진 속 프리미어 중첩의 직접 원인은 원본 SRT 없이 확정하지 못했다. 파일에서 재현한 일반 자막 겹침과 편집 프로그램의 표시 문제를 구분한다. 프리미어 프로 2026에 실제 가져오는 검증은 하지 않았다.
- SRT 첫 0~2초 안내는 기존의 명시적 중첩 예외로 유지한다. 형식 시간 해상도보다 짧은 발화의 한계도 유지한다.
- 운영 배포, 실제 고객 음원 전사, 외부 전사 API 호출은 수행하지 않았다.
