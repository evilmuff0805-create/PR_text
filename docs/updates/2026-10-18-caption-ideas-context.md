# 자막 아이디어의 문맥·의미 보존 보완

자막 아이디어가 앞뒤 대사의 조건을 놓치거나, 재미·감성 표현을 만들면서 확인되지 않은 반응과 결말을 덧붙일 수 있었다. 기존 네 유형의 문체에 문맥·문법 판단 기준을 보충하고, 충돌하는 장면에만 예외를 적용했다.

## 생성 기준

- 예능은 짧은 댓글 리듬·대비·이름 말장난을 유지한다. 웃음의 근거가 없는 정지 장면에는 없는 과거·반복 행동으로 농담을 채우지 않는다.
- 상황은 명사구·자연스러운 한자어·13자 내외 선호를 유지한다. 주체·목적·부정·조건을 잃으면 28자 안에서 필요한 만큼 쓴다.
- 강조는 힘 있는 호흡·근거 있는 평가를 유지한다. 조건·가능성·수량을 확정 사실로 올리지 않는다.
- 감성은 따뜻함·가벼운 시성을 유지한다. 확인된 행동과 사물을 바탕으로 쓰고, 미제공 안도·용서·감정 변화나 바람의 성취를 사실처럼 만들지 않는다.

한 사람의 반응과 그 사람만의 반응, 정보 부재와 부정 사실, 바람과 약속, 확인된 발언과 임의의 해석을 구분한다. 명백한 표기 오류는 점검하면서 의도적 축약·말장난·반복을 자동 표준화하지 않는다. 기존 예시는 어조 참고로 유지하고 새로운 익명 합성 문맥 예시를 유형별로 보충했다.

아이디어 모델 기본 `gpt-5.6-luna`와 `CAPTION_IDEAS_MODEL` 우선순위, 기존 안전성 검사, 세 후보·각28자·복사·90일 내역·성공5회당1분 정산은 유지한다. 전사·교정·자막 시간 계산에는 적용하지 않는다.

## 초점과 문맥 전달

독립 아이디어 탭은 기존 한 입력창과 `POST /api/caption-ideas`를 사용한다. 구간 편집의 아이디어 버튼은 `POST /api/caption-ideas/context`로 선택한 대사와 앞뒤 참고 대사를 구분한다.

```json
{
  "requestId": "클라이언트가 생성한 UUID",
  "mode": "situation",
  "text": "선택한 대사 원문",
  "context": { "before": ["앞 대사"], "after": ["뒤 대사"] }
}
```

각 배열은 최대 두 줄이며 초점과 문맥의 합은 Unicode 코드 포인트500자다. 초점 전체를 먼저 보존하고 먼 문맥부터 한 줄씩 제외한다. 제외 사실과 전송할 문맥을 화면에서 확인할 수 있다. 초점이500자를 넘으면 읽기 전용 원문에서 아이디어 대상 부분만 선택하며 편집 대사와 시간은 변경하지 않는다.

새 경로는 기존 인증·기능 게이트·생성·정산 처리와 분당5회 제한 버킷을 공유한다. 초점과 앞뒤 문맥 전체를 입력 안전성 검사에 포함한다. 구버전 서버의404에서 기존 경로로 자동 우회하지 않는다.

## 요청 복구와 화면 보호

동일 계정·로그·구간·내용·유형·문맥의 미확정 요청만 같은 UUID로 재시도한다. 입력 변경 또는 성공 후 새 생성은 새 키를 사용한다. 즉시 중복 클릭을 차단하고, 구간·유형·계정을 바꾼 뒤 늦게 온 응답은 현재 화면에 적용하지 않는다. 새 요청 실패 시 이전 성공 후보는 유지하고 이전 입력의 결과라는 점을 표시한다.

응답 유실은 생성이나 차감 실패로 단정하지 않는다. 같은 키로 완료 결과를 복구한다. 클라이언트 요청 키의 보호이며 서버 입력 fingerprint나 진행 중 AI 실행 전체를 잠그는 DB 기능을 추가한 것은 아니다.

## 검증과 한계

실제 같은 모델의 비교에서 기존240토큰 한도가 추론에 소진되어 빈 결과가 발생했다. 최종 요청은512토큰으로 조정하고 기준선도 같은 한도로 비교했다. 최대 두 번의 생성 시도와 추론·sampling 기본값은 유지한다. 길이 한도·거절·공급자 실패는 원문 없이 구분해 관측한다.

- Node22 전체623테스트, 프로덕션 빌드와 diff 검사를 통과했다.
- 실제 JSX 모의 동작으로 응답 유실·같은 부분 재선택·A→B→A·계정/로그/구간 전환·원문 편집·404/409·Unicode 경계와 이전 성공 결과 보존을 확인했다.
- 격리 PostgreSQL17에서 마이그레이션, 기존 작업·동시성 회귀와 아이디어 정산을 확인했다. 실제 Express·합성 공급자·격리 DB를 연결한 검증은 운영 Supabase HTTP나 실계정 검증과 구분한다.
- 단일·묶음의 원문·시작/끝·편집 저장·SRT/ASS/ZIP 출력 불변을 기존 회귀와 독립 검수로 확인했다. 실제 고객 음원을 새로 전사하거나 Premiere에서 가져오는 검증은 하지 않았다.

실제 AI 평가는 고객 원고·연락처를 보내지 않고 새 익명 합성24장면을 사용한다. 개발16장면과 미사용 봉인8장면, 원시 모든 시도와 최종 후보, 지침 비교와 문맥 제품 비교를 분리한다. 개발 과정의 오류·잘림·예산 개정도 보존한다. 유한 표본의 평가가 앞으로의 무오류를 보장하지 않으며, 영상·음성 없이 제공되지 않은 행동·표정·마음은 알 수 없다.
