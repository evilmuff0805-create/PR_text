# 일반 단일 자막 표시 유지와 한국어 교정

일반 단일 파일에서 짧은 자막 사이 공백으로 화면이 깜빡이는 문제를 줄인다. 최종 자막을 분할한 뒤 다음 자막까지의 공백이 양수이고 1초 이내면, 앞 자막의 표시 종료만 다음 자막 시작까지 유지한다. 예를 들어 앞 자막이 3.250초에 끝나고 다음 자막이 3.900초에 시작하면 앞 자막도 3.900초까지 표시한다. 문장이나 대사를 합치지 않는다.

1초 초과의 공백, 마지막 자막, 다화자는 원래 끝을 유지한다. 사람별 묶음 ZIP과 묶음 결과의 개별 SRT·ASS, 기록 재다운로드도 원래 발화 끝을 사용한다. 묶음에서 다른 사람의 트랙으로 넘어가는 동안 자막을 늘리지 않는다.

일반 결과·기록의 SRT·ASS 재다운로드부터 새 표시 정책을 적용할 수 있다. 원본·저장된 편집본·단어 시간은 바꾸지 않는다. 첫 0~2초 시작 안내는 이 처리 바깥에서 정확히 한 번 넣고 TXT는 바꾸지 않는다. SRT는 밀리초 절대시간이고 ASS는 기존 센티초 반올림을 사용한다. 1초를 고정 30프레임으로 환산하거나 시퀀스 fps에 맞춰 재배율하지 않는다.

묶음 기록은 소유권을 확인한 뒤 기존 작업의 `batch_id` 매핑만 읽어 출력 정책을 전달한다. 메타 조회가 불확실하면 저장된 발화 끝을 보존한다. 새 DB 컬럼·마이그레이션·정산·작업 상태 변경은 없다.

한국어 교정 지침의 절대적인 단어 보존 표현을 정리하고, 명백한 맞춤법·활용·사실상 동음인 받아쓰기 오류를 최소 수정하도록 허용·유지 예시를 구분했다. 같은 청크의 앞뒤 줄은 판단 문맥으로 읽되 줄 수·순서·대사 위치를 유지한다. 음식 문맥의 “나물을 묻혀서”는 “나물을 무쳐서” 교정 예시이며, 표면에 양념을 묻히거나 땅에 묻힌다는 뜻과 애매한 문맥은 보존한다. 특정 단어를 프로그램에서 일괄 치환하지 않는다. 모델·호출 횟수·동시 처리·단어 정렬은 그대로다.

이 교정 후보는 변경 전 원문 보호 검사도 허용했다. 따라서 실제 누락 원인을 보호 검사로 확정하지 않는다. 새 지침이 실제 모델의 정답률을 얼마나 바꾸는지도 합성 후보 테스트만으로 판정할 수 없다. 숫자 값·소수점·부호·순서·통상 단위가 바뀐 후보는 해당 줄만 원문으로 되돌리며, 수치와 단위의 띄어쓰기는 허용한다. 기존 반복 횟수·추임새·순수 글자 추가/삭제 보호도 유지한다. 한글 수사·이름·모든 의미 변경을 자동 검증하는 기능은 아니다.

로컬 Node.js22 전체 테스트 **559/559**(실패·건너뜀0), production build77모듈·공개 HTML5종, 공백 검사를 통과했다.

검증은 실제 SRT·ASS 생성, 경계값 0/0.999/1/1.001초, 분할 뒤 마지막 조각, 단어 정렬과 compact 저장 결과, 시작 안내, 다화자, ZIP, 소유한 기록의 단일/묶음 분기, 인증·불확실한 메타 조회, 실제 Express 경로와 JSX 컴포넌트의 정책 전달을 대상으로 한다. 교정 후보는 합성 corrector를 사용해 문맥 예시·반복·수치 보호와 시간 불변을 검증한다. 로컬 OpenAI API 키가 없어 실제 교정 모델·고객 음원·Premiere 가져오기 평가는 실행하지 않았다. 운영 배포는 별도 단계다.
