# 무음 구간 자막 관측

## 목적과 범위

일반 Whisper 변환에서 무음 구간에 환각 자막이 생성되는 사례를 재현하기 전, 후보 빈도와 입력 자료의 신뢰도를 개인정보 없이 관찰합니다. 이 기능은 **shadow 관측 전용**입니다. 후보 자막을 삭제하거나 전사 결과, 타임코드, 정산, 사용자 응답을 바꾸지 않습니다. 다화자 변환에는 적용하지 않습니다.

## 작동 방식

- `SILENCE_OBSERVATION_MODE`는 기본 `off`이며 `shadow`일 때만 관측을 예약합니다. off에서는 음원 파일 쓰기와 ffmpeg 실행이 없습니다.
- 기존 provider 요청이 끝난 뒤 백그라운드에서 원본 오디오를 한 번 분석합니다. 오디오 채널을 모노로 합치지 않고 ffmpeg의 `silencedetect`를 실행하며 시작 시각을 0 기준으로 보정합니다.
- ffmpeg 스레드는 1개, 작업 전체 제한은 10초, stderr는 최대 4MiB입니다. 임시 원본 파일은 성공·실패·취소 후 정리합니다. 서버 종료 시 실행 중 관측을 취소하고 정리를 기다립니다.
- ffmpeg 무음 탐지는 `-50dB`, 최소 `0.5초` 실험 설정입니다. `silencedetect`는 채널을 모노로 합치지 않고 입력 오디오 스트림의 채널을 분석합니다.
- 메모리 추가 보유를 줄이기 위해 32MiB 초과 원본과 20,000개 초과 segment는 관측을 건너뜁니다. 동시 관측은 인스턴스당 한 건만 허용하며 나머지는 건너뜁니다. 따라서 결과는 전체 트래픽의 무작위 표본이 아니며, 큰 파일·동시 요청이 많은 시간대가 덜 반영됩니다.
- 후보는 유효한 시간·신뢰도 메타데이터, `no_speech_prob >= 0.8`, `avg_logprob <= -0.5`를 모두 만족하고, segment의 앞뒤 0.25초 여백까지 ffmpeg 무음 구간 안에 완전히 들어간 경우입니다. 스피커 정보가 있거나 값이 없거나 범위가 잘못된 자료는 후보에서 제외합니다. 임계값은 보수적 실험값이며 오탐을 포함할 수 있습니다.
- 로그는 결과 수, 무음 구간 수, 유효 메타데이터 수, 소요시간, 실패·건너뜀 분류와 기존 provider 요청 식별자만 기록합니다. 자막 문장, 파일명, 계정 식별자는 기록하지 않습니다. 관측 오류와 로그 출력 오류는 변환 성공 결과에 영향을 주지 않습니다.

## 위험과 한계

- 낮은 음량의 실제 대사가 무음으로 분류될 수 있습니다. 합성 한국어 TTS 원본과 -20/-40dB 음량 조정본은 가상 공급자 메타데이터(`no_speech_prob=0.95`, `avg_logprob=-1.2`)를 넣었을 때 후보 0건이었습니다. -60dB로 낮춘 TTS에는 실제 합성 대사가 남아 있었지만 동일한 가상 메타데이터로 후보 1건이 나왔습니다. 이는 자동 삭제를 금지해야 할 오탐 반례입니다. 메타데이터는 실제 provider 응답이 아니며, 이 검사는 고객 음원 검증도 아니고 작은 목소리·배경 음악·환경 소리 전반의 오탐률을 설명하지 않습니다.
- 10초 제한, 32MiB·segment 수 제한, 한 건 동시 실행 때문에 일부 음원은 빠집니다. busy·size skip 집계와 관측 완료 수를 함께 보며 후보 비율을 정확도나 전체 사용자 비율로 해석하지 않습니다.
- 백그라운드 작업은 한 개의 제한된 원본 Buffer를 최대 10초 동안 더 보유합니다. 관측은 변환 요청의 응답 시간을 기다리게 하지 않습니다. 강제 프로세스 종료 시에는 임시파일 정리가 보장되지 않을 수 있습니다.
- 관측 후보만으로 자동 삭제·보정 정책을 만들지 않습니다. 작은 음성 삭제 위험을 포함한 정밀도·재현율 검증과 실제 원본 검수가 별도 승인되기 전에는 shadow 모드만 유지합니다.

## 켜기와 되돌리기

1. 배포 환경에서 `SILENCE_OBSERVATION_MODE=shadow`를 설정하고 새 인스턴스가 시작될 때 `[transcription.silence_observation] {"mode":"shadow"}` 로그를 확인합니다.
2. 개인정보 없는 집계 로그의 `outcome`, `validConfidenceMetadataCount`, `silenceIntervalCount`, `candidateCount`, `durationMs`, `reason`을 확인합니다. provider 요청 식별자는 해당 요청의 기존 처리 기록과 연결할 때만 사용합니다.
3. 오류, 예상치 못한 CPU·메모리 영향, 임시파일 문제가 보이면 환경변수를 `off`로 바꾸고 재배포합니다. `off`에서는 새 관측 작업이 예약되지 않습니다.

기능은 fail-soft입니다. ffmpeg 미설치, 형식 오류, 처리 제한 초과는 분류된 집계만 남기고 변환 결과는 유지합니다.
