# 사람별 오디오 묶음 변환

## 사용 방법

1. 각 사람의 녹음을 **같은 영상의 0초부터** 내보낸다. 앞부분 무음을 제거하지 않는다. 파일마다 첫 발화를 0초로 옮기면 앱이 원래 위치를 자동으로 복원할 수 없다.
2. 변환 화면에서 사람별 오디오 묶음을 선택하고 최대 5개를 올린다. 인물 이름과 파일 순서, 공통 언어를 확인한다. 한 파일에 여러 사람의 목소리가 섞인 녹음을 자동 분리하는 방식은 아니다.
3. 파일별 업로드와 서버 길이 확인이 끝나면 총 차감 시간을 확인하고 변환을 시작한다. 파일별 분 단위 올림, 최소 1분의 합계를 사용한다. 20분 파일 3개는 60분이다. 앞부분 무음도 파일 길이에 포함된다.
4. 파일마다 완료 상태와 자막을 확인하고 편집한다. 편집 저장이 완료된 내용으로 SRT ZIP을 받는다. 일부 파일이 실패한 경우 **완료된 N개 다운로드**를 선택할 수 있다.
5. 프리미어 프로에서 SRT들을 각각 가져와 인물별 자막 트랙의 같은 시작점에 배치하고 트랙마다 스타일을 지정한다. 자동으로 프리미어 트랙을 만들지는 않는다.
6. ZIP 사용안내에서 전사 완료 건수와 실제 포함된 SRT 파일 수를 확인한다. 인식된 대사가 없는 완료 건은 빈 SRT를 만들지 않으며 ZIP에서도 제외된다.

앞부분 무음과 파일별 시작 시간을 유지하고, 인물 간 동시 발화는 각 SRT에 따로 남긴다. 일반 단일 파일의 1초 이내 공백 표시 유지 정책은 묶음 ZIP·묶음 결과의 개별 파일·기록 재다운로드에 적용하지 않는다. 자막에 표시하는 시간은 인식기가 추정한 발화 시간이다. SRT는 밀리초 형식이며 fps 정보가 없으므로 시퀀스 fps는 편집 프로그램에서 설정한다. 29.97fps에 맞춰 시간을 재배율하거나 첫 대사를 0초로 당기지 않는다.

## 복원과 실패 처리

- 업로드가 서버에 접수된 파일과 작업은 새로고침·로그인 복귀 뒤 확인할 수 있다. 업로드를 마치지 못한 원본은 같은 파일을 다시 선택해야 할 수 있다.
- 완료된 파일은 실패 파일의 재시도로 다시 전사하지 않는다. 실패가 확정된 파일만 재시도할 수 있으며 완료된 체크포인트는 저장 마무리부터 이어간다.
- 인식된 대사가 없는 결과는 **인식된 대사 없음 · 검토 필요**로 표시한다. 실제 무음이라는 판정이 아니다. 빈 SRT는 ZIP에서 제외되므로 원음을 확인한다.
- 다른 마이크에 같이 들어간 목소리를 자동으로 제거하거나 여러 파일에서 중복 대사를 지우지는 않는다.
- ZIP 생성 실패·재다운로드는 새 전사나 추가 차감을 하지 않는다. 원본 음원 보관 정책을 늘리는 기능은 아니다.
- 서로 다른 파일의 시작점을 파형으로 자동 정렬하거나 BWF 시작 메타데이터, 수동 오프셋, 동영상 내부의 여러 오디오 트랙을 추출하는 기능은 이번 범위에 포함하지 않는다.

## 운영 설정과 검증

**코드 배포 전에** `supabase/migrations/20261017014800_person_audio_batches.sql`까지 적용한다. 신규 접수가 꺼져 있어도 일반 worker의 정리 작업은 새 RPC를 사용하므로 코드만 먼저 배포하지 않는다. 스키마 반영 후 `TRANSCRIPTION_BATCHES_ENABLED=true`로 신규 묶음 접수를 활성화한다. 기존 단일 변환의 `TRANSCRIPTION_OPERATIONS_ENABLED`는 별도 설정이다. 일반 변환 worker는 접수 설정을 꺼도 기존 작업의 처리·취소·정리를 이어가야 한다. 진행 작업이 남은 상태에서 스키마나 worker를 제거하지 않는다.

일괄 시작은 서버에서 모든 파일의 길이를 검증한 뒤 한 DB 트랜잭션에서 파일별 크레딧을 예약한다. 부모 묶음에는 추가 예약이 없다. 동시 시작·응답 유실 재시도는 같은 요청으로 복원하며, 실패·취소 환불은 기존 예약 원천과 만료 규칙을 따른다. 결과가 불확실한 작업은 완료·실패 확인 전에 재접수하거나 임의 환불하지 않는다.

한 사용자에게 활성 묶음은 최대 1개이고, 기존 단일 작업과 묶음을 합쳐 활성 접수 단위는 최대 3개다. 묶음 내부에서는 한 번에 한 파일을 처리하며 긴 파일 내부의 기존 청크 동시 처리 한도는 유지한다. ZIP은 소유한 묶음의 최신 저장된 편집본을 파일마다 독립 생성한다.

DB 변경 검증은 운영 DB가 아닌 PostgreSQL 17의 일회용 데이터베이스에서 전체 마이그레이션을 재생하여 수행한다. 기존 `db-operations.cjs`, `db-concurrency.cjs`, 신규 `db-batches.cjs`와 전체 Node 테스트·production build를 실행한다. 합성 음원·모의 API 테스트와 실제 음원·프리미어 가져오기 검증을 구분해 기록한다.
